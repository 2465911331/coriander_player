# Coriander Player 1.5.6：Material Design 3 针对性优化方案

分析日期：2026-10-21。

依据：当前 1.5.6 源码、1.5.6 音乐库预览、此前 1.5.5 的播放页与设置页截图。后两类截图仅辅助理解，相关结论均再对照当前代码。本文是方案分析，尚未实施；对比度、实际帧耗时和完整键盘流程尚未实测。

## 1. 建议方向

建议以“清晰的音乐库 + 稳定的底部播放区 + 可连续展开的播放详情”为产品骨架，分三轮推进：

1. 首轮统一基础布局、状态和样式，并让动效开关覆盖所有界面过渡。
2. 第二轮改善常用播放操作、搜索、视图切换和设置组织。
3. 第三轮设计连续展开动效与宽屏播放队列。

黑胶唱片、波浪/真实波形、频谱与封面背景继续作为产品特色。它们属于播放器的定制表现，应与主题和交互体系协调。

## 3. 首轮：优先解决的具体问题

工作量为基于代码结构的相对估计，不是排期承诺。

| 优先级 | 当前情况与影响 | 建议方案 | 预期收益 | 工作量 |
| --- | --- | --- | --- | --- |
| P0 | 主内容和迷你播放器通过 Stack 叠放，截图中播放条遮住卡片下部。滚动区虽预留底部空间，当前可视行仍可能被覆盖 | 为底部播放区预留真实布局空间，内部保留悬浮圆角条的外观；统一处理边距和缩放 | 歌名、操作与设置项可完整阅读和点击 | 中 |
| P0 | 卡片分支订阅当前歌曲与播放状态；列表分支主要依据定位参数 `focus` 着色，缺少相同的正在播放提示 | 列表、卡片、搜索结果和歌曲详情行统一显示当前歌曲及播放/暂停状态 | 切换视图后仍能立即定位当前歌曲 | 小至中 |
| P0 | 字号、形状和间距分散。例如页面标题因副标题有无分别使用 32、28；卡片标题/说明为 15、12 | 通过 TextTheme 和组件主题定义页面标题、歌曲名、辅助信息、状态标签；形状按用途分类 | 页面看起来属于同一个产品，中文字号和缩放更稳定 | 中 |
| P0 | 卡片和歌词等已读取动效偏好，路由过渡仍直接使用固定时长及曲线 | 统一动效策略入口；关闭动效时跳过非必要位移与缩放，保留明确状态变化 | “关闭动效”设置的行为一致 | 小至中 |
| P0 | 歌曲列表固定行高 64，放大字体后存在容纳两行文字不足的风险；卡片菜单限制为 28×28 | 动态计算或分档设置行高；按鼠标、键盘和触控分别验证目标区域与焦点 | 减少大字号溢出和小目标误点 | 中 |

不同圆角数值本身不构成 M3 问题。现有封面 12、卡片 18、菜单 20、播放条 8，应先归入“封面、内容容器、菜单、播放浮层”等角色，再决定哪些采用组件默认，哪些保留品牌定制。

配色同样以用途组织：页面、内容容器、浮层分别建立层级；文字、图标使用与背景匹配的颜色角色。自定义背景和透明度需要验证最终合成后的可读性。

规范依据：[M3 Color roles](https://m3.material.io/styles/color/the-color-system)、[M3 Typography](https://m3.material.io/styles/typography/applying-type)。

## 4. 第二轮：提高日常操作效率

### 4.1 迷你播放器

现有底部播放条包含封面、歌曲信息和播放/暂停，上一首、下一首及队列入口在完整播放页中。

建议宽窗口采用“封面与歌曲信息—上一首/播放/下一首—队列入口”的结构。音量可通过独立按钮展开，避免挤压歌名。窄窗口按操作优先级收起次要按钮，保持播放主操作稳定。

展开播放页的点击区域与独立控制按钮分别处理，避免点击切歌、队列时同时展开页面。无歌曲时，操作状态与提示应清楚。

### 4.2 音乐库工具栏

现有视图切换是单个图标，含义主要靠悬停提示；排序项使用自定义胶囊。小窗口通过操作数组顺序折叠动作。

建议：

- 宽窗口用“列表 / 卡片”分段按钮，直接显示当前模式；窄窗口可保留更紧凑的控件。
- 排序与升降序组成清楚的操作组，选中项可见。
- 将刷新、排序、视图等动作显式分配优先级，窄窗口按任务收纳。
- 普通操作保持次要强调，随机播放、新建歌单等主要动作保留主要强调。

少量选项、视图切换适合 SegmentedButton，是官方组件的明确使用场景。来源：[SegmentedButton](https://api.flutter.dev/flutter/material/SegmentedButton-class.html)。

### 4.3 搜索

现有流程为进入搜索页，在居中 TextField 输入并回车，再进入分类结果页。搜索输入框之间已有 Hero。顶栏长胶囊实际显示歌词，外形可能让新用户联想到输入框，这是设计判断，尚未做用户测试。

建议使用 SearchBar / SearchAnchor 构建明确的搜索入口，显示歌曲、艺术家、专辑建议，并保留完整结果页。增加明确的清空、空查询、无结果状态。键盘提供聚焦和退出路径；快速输入时只呈现最新查询结果。

歌词区域继续保留，并通过只读信息样式、歌词标识和可选显示方式与搜索操作区区分。调整顶栏时要保留窗口拖拽区域。

搜索视图可按桌面与窄窗口分别呈现。来源：[SearchAnchor](https://api.flutter.dev/flutter/material/SearchAnchor-class.html)。

### 4.4 设置与操作反馈

外观设置已有折叠分组和预览；整页仍是较长的连续列表，主题、系统色、明暗和字体设置分散。

建议整页按“播放与窗口、声音、音乐库、外观与动效、关于”组织。外观中集中放置主题、字体、卡片、封面、进度、频谱与歌词；常用选项先显示，细节参数放在对应小组中。

歌单删除目前直接移除并保存。建议提供清晰的结果反馈及撤销机会，文案明确作用于歌单；该操作不涉及删除原音乐文件。其他常规反馈也采用一致的提示位置与时机。

## 5. 第三轮：有连续性的动效与宽屏布局

### 5.1 迷你播放条到完整播放页

目前完整播放页从屏幕底部整体滑入，封面没有与迷你播放条建立共享过渡。

建议让封面从播放条中的位置连续过渡到播放页封面区域，歌曲信息和控制区随后呈现。黑胶模式下，先建立封面位置关系，再显现唱片外圈，避免将小方封面突然替换成大唱片。关闭时沿对应关系收回。

需要处理连续展开/返回、展开过程中切歌、窗口改变尺寸，以及关闭动效的情况。过渡期间不要创建第二套播放状态或音频实例。

### 5.2 切歌、歌词与队列

播放页已有封面、背景和歌词过渡。当前部分过渡分别使用 150、170、350、650ms 等参数，适合整理为有职责的动效定义；不同层级可以继续采用不同节奏。

M3 Expressive 将位置、尺寸等 Spatial 变化与颜色、透明度等 Effects 变化分开，后者应避免越界回弹。官方页面仍将 Flutter 的这套动效系统实现标为 Unavailable，应按本地 Flutter 3.32.8 的能力适配，复杂弹簧行为单独实现与验证。

来源：[M3 Motion physics system](https://m3.material.io/styles/motion/overview/how-it-works)。

建议实施重点：快速切歌时丢弃过时结果；歌词滚动不抢占用户正在浏览的位置；队列展开/收回可打断；播放按钮的形状反馈与实际状态保持同步。进度拖动保持精确、即时。

### 5.3 宽屏队列与导航

当前播放页的队列会替换歌词区域；音乐库中没有同等的常驻队列侧栏。可在足够宽的窗口提供可折叠的辅助面板，让用户浏览音乐库或歌词时管理队列。窄窗口使用独立视图或弹出面板。

已有导航栏/抽屉自适应应保留。宽屏可以增加手动收起侧栏，搜索、设置的分组位置再评估；导航变化需要同时验证返回行为、滚动位置和多选状态。

这一项是按 M3 辅助面板布局思路提出的产品建议，不是桌面播放器必须采用的固定布局。参考：[M3 Canonical layout examples](https://m3.material.io/foundations/layout/canonical-examples/overview)。

## 6. 统一交互状态

以下状态已有部分实现，建议跨列表、卡片和队列统一：

| 状态 | 建议表达 |
| --- | --- |
| 默认 | 清楚的歌曲信息和稳定布局 |
| 鼠标悬停 | 轻微表面反馈，显示快捷操作 |
| 键盘聚焦 | 独立、清楚的焦点指示，操作可发现 |
| 当前正在播放 | 文字或图标标记，暂停操作可用 |
| 当前已暂停 | 保留当前歌曲身份，呈现继续播放 |
| 多选选中 | 选择标记与容器样式，并保持已存在的防误播处理 |
| 暂不可用 | 禁用状态及必要原因，避免外观上仍像可执行操作 |

不把鼠标悬停当作唯一的操作发现方式。桌面精确输入可以较紧凑；触控目标则需扩展，并与图标本身尺寸区分。来源：[Flutter 平台目标尺寸](https://api.flutter.dev/flutter/material/ThemeData/materialTapTargetSize.html)、[官方无障碍交互指导](https://developer.android.com/guide/topics/ui/accessibility/apps)。

## 7. 验收建议

1. 布局：以逻辑宽度约 540、900、1440 为样本，并测试 100%、125%、150% 显示缩放。底部播放条不遮挡内容或可点击区域，队列不会挤压关键操作。
2. 文字：验证长中文歌名、混合英文与字体放大。固定高度的行改为能容纳目标字号；空内容、缺封面同样完整。
3. 配色：浅色、深色、多种种子色和封面背景分别检查。依据文字规模验证对比度；当前未测量，不能直接判定现有颜色不合格。
4. 状态：同一歌曲在卡片、列表、搜索与队列中的当前状态一致；多选、焦点和正在播放可分别识别。
5. 键盘：Tab、激活、Esc、搜索聚焦及既有进度键盘操作可完成主要流程；文字输入时不误触全局播放快捷键。
6. 动效：关闭动效后验证所有路由与面板；快速切歌、连续返回、窗口缩放不出现旧封面闪回或失效操作。使用性能工具检查帧耗时，后台保持省电策略。
7. 回归：托盘恢复/退出、记住播放、队列、无缝播放、音量统一和智能歌单保持正常；后续发布继续验证覆盖安装与用户偏好迁移。
